## 生成这些文件

图片（先在仓库根目录，脚本里的图片路径都是 `docs/...` 相对路径）：

```bash
python tools/design_d.py     # 图-主视图.png（卡片式提交图）
python tools/arch_fig.py     # 图-架构.png
python tools/seed_real.py    # 演示数据（data/state.json + data/files/）
```

文档：

```bash
python tools/func_doc.py     # → docs/项目Git-功能设计稿v1.0.docx（嵌 图-主视图、图-3）
python tools/soft_doc.py     # → docs/项目Git-软件设计稿v1.0.docx（嵌 图-主视图、图-架构）
```

转 PDF（走 Word COM，必须先进那个目录再执行）：

```powershell
cd "D:\03_code_list\Claude code\任务64-千问大赛"
python .\temp\topdf2.py "<docx 绝对路径>" "<pdf 绝对路径>"
```

数据分析（会改 `data/`，改完记得重出文档和截图）：

```bash
node tools/ingest.js batch.json --dry-run   # 导入预演：只出统计，不写盘
node tools/eval_qa.js                       # 20 题简单问法
node tools/eval_hard.js                     # 20 题换说法（分类打分）
```

## 改设计时的三条规矩

1. **先改脚本，再看图，最后改文档**：图是 `tools/design_d.py` 画的，文档是 `tools/*_doc.py` 生成的。
   手改 PNG 或手改 docx，下一次重出就全丢——所以宁可多写几行 Python。
2. **数字只能来自实测**：评估分数抄 `tools/eval_*.js` 的终端输出，导入统计抄 `ingest` 的返回。
   不写“预计”“大概”“应该能到”；测不出来就写测不出来。
3. **图、文档、实现不一致时，以图为准**：图先定，文档跟着改，实现最后对齐；
   每次重出 docx + pdf 都要过三关——**没有 `[缺图：...]` 灰字**、**页数在范围内**（功能稿 11–13 页，软件稿 12–14 页）、
   **抽查两页图没糊**。三条不过，就别提交。
